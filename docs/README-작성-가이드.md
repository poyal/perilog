# 페리로그 README 작성 가이드

루트 [README](../README.md)는 처음 사용하는 분이 설치부터 기록·재고 관리·백업·업데이트까지 따라 할 수 있는 **사용자 매뉴얼**로 유지합니다. README를 새로 쓰거나 기능 변경·릴리즈에 맞춰 갱신할 때 먼저 이 문서를 읽고 따릅니다.

## 1. 문서의 목적과 독자

- 앱을 처음 설치한 사용자가 다음에 누를 메뉴와 버튼을 찾을 수 있어야 합니다.
- 기능 이름을 나열하는 데 그치지 않고, 입력·저장·결과 확인까지 설명합니다. 기본 사용 흐름은 README 안에서 끝낼 수 있게 합니다.
- 제목은 **페리로그 사용자 매뉴얼**로 유지합니다. 특정 버전을 제목이나 소개의 중심으로 삼지 않습니다.
- 한국어 존댓말과 짧고 구체적인 문장을 사용합니다. 실제 메뉴·버튼 이름은 **굵게** 표시하고, 조작 순서는 번호 목록으로 씁니다.
- 앱의 입력·계산·보관 동작을 설명합니다. 예시 수치와 물품 구성을 사용자의 치료 기준이나 권장 처방처럼 표현하지 않습니다.

## 2. README의 기본 구성

상단에는 아이콘, 앱 소개, 지원 Android 버전, 로그인 여부, 기록 저장 위치, 다운로드·화면·문의 링크를 간결하게 둡니다. 처음 사용할 때의 순서와 목차를 이어서 제공합니다.

다운로드는 항상 [최신 릴리즈](https://github.com/poyal/perilog/releases/latest)로 연결합니다. 설치 파일 이름을 특정 버전으로 고정하지 말고, 사용자가 릴리즈에서 `.apk` 파일을 고르는 방법을 설명합니다.

본문은 다음 사용 순서를 기본으로 삼습니다. 기능이 바뀌면 해당 절을 고치되, 새 버전의 기능만 남기거나 기존 사용 절차를 삭제하지 않습니다.

| 순서 | 절 | 사용자가 할 수 있어야 하는 일 |
| --- | --- | --- |
| 1 | 설치하기 | APK 다운로드, 출처 허용, 설치·실행, 기존 앱 위에 업데이트 |
| 2 | 화면과 메뉴 익히기 | 홈·기록·통계·재고·설정의 위치와 역할 찾기 |
| 3 | 처음 한 번 준비하기 | 물품·보유 수량·사용 구성 등록, 계산 기준 확인, 백업 준비 |
| 4 | 매일 기계투석 기록하기 | 시작 전·종료 후 입력, 날짜 선택, 구성 확인, 저장·완료 확인 |
| 5 | 추가투석 기록하기 | 물품 사용 등록, 선택 배액 기록, 단위 선택, 저장 |
| 6 | 기록 조회·수정·삭제하기 | 목록·달력·표·통계 조회, 기록 수정·삭제, 잘못된 사용 취소 |
| 7 | 입고와 재고 관리하기 | 입고일·수량 입력, 현재 수량 맞추기, 사유를 적어 일부 수량 추가·차감 |
| 8 | 화면·알림·앱 잠금·화면 보호 설정하기 | 테마·알림·잠금·보호 변경과 설정 저장 |
| 9 | 병원 일정과 연락처 관리하기 | 진료과·치료 항목 등록, 진료과별 예약시간과 다음 예약 재사용, 연락처 아바타·연결 허용 |
| 10 | 백업·복원·기기 변경하기 | 내보내기, 자동 백업, 복원, 새 기기에서 폴더 연결 |
| 11 | 업데이트와 앱 정보 확인하기 | 정보 페이지, 업데이트 조회·다운로드·검증·설치, 구버전 수동 업데이트 |
| 12 | 자주 확인하는 내용 | 미완료·날짜·재고·백업·오프라인 상황 해결 |

마지막에는 문의·오류 신고와 전체 화면, 텍스트 사용 안내, 변경 이력, 개발·검증 문서 링크를 둡니다. 목차에는 현재 README의 명시적 앵커(`install`, `setup`, `backup` 등)를 사용하고, 절을 바꿀 때 연결도 함께 확인합니다.

## 3. 사용 절차를 쓰는 방법

각 작업은 **진입 위치 → 입력·선택 → 저장·확인 버튼 → 결과** 순서로 씁니다. 데이터나 재고에 영향을 주는 작업은 그 영향도 바로 옆에 설명합니다. 버튼 이름과 동작은 현재 앱 화면과 구현을 확인하며, 계획 문서만 보고 구현된 것으로 쓰지 않습니다.

입고 안내의 예시는 다음과 같습니다.

> 1. **재고 → 입고 등록**을 엽니다.
> 2. 입고일과 받은 품목별 EA 수량을 입력합니다.
> 3. 필요한 경우 입고 메모를 적습니다.
> 4. **함께 저장**을 누릅니다. 저장한 내용은 **재고 → 이력**에서 종류를 **입고**로 선택해 확인·수정할 수 있습니다.

페리로그에서는 다음 차이를 사용자가 오해하지 않도록 관련 절에 남깁니다. 동작이 변경되면 구현과 검증 결과를 확인한 뒤 설명도 함께 수정합니다.

- **빈칸과 0:** 미입력 값을 0으로 취급한다고 설명하지 않습니다.
- **초안과 저장:** 입력 중 보관되는 초안과 저장한 물품 사용에 따른 재고 차감을 구분합니다.
- **오늘과 어제:** 아침에 전날 기록을 마치는 방법과 새 기록의 기본 날짜를 설명합니다.
- **기록 삭제와 사용 취소:** 기록 삭제 시 연결된 사용을 함께 취소하는 동작, 삭제 직후 되돌리기, 이미 취소한 사용의 중복 복원 방지와 이전 버전에서 남은 사용 취소 경로를 설명합니다.
- **계산 기준과 실제 입력:** 제수량 계산에 쓰이는 설정값과 과거 기록에 보존되는 기준을 설명합니다. 배액무게와 부피, 기계투석과 추가투석 결과를 임의로 환산·합산하지 않습니다.
- **내보내기와 가져오기:** 가져오기는 현재 데이터를 전체 교체하며, 앱 내부 보호 백업과 외부 백업 파일은 별개임을 설명합니다.
- **업데이트와 삭제:** 기존 앱 위에 설치하는 순서를 안내하고, 앱 삭제 시 내부 데이터도 지워진다는 점을 해당 단계에 둡니다.
- **다운로드와 설치:** 파일 검증, Android 설치 확인, 설치 취소 후 Download 폴더에 남은 파일을 여는 방법을 설명합니다.

## 4. 스크린샷 배치와 관리

스크린샷은 해당 조작 설명 가까이에 둡니다. 사용자가 화면에서 메뉴와 입력 위치를 찾는 데 필요한 장면을 고르고, 설명과 상관없는 화면을 상단에 길게 모으지 않습니다.

- 실제 앱의 현재 화면을 사용하며, 예시 데이터라는 점을 밝힙니다. 실제 사용자 기록·개인 백업·키·비밀번호는 촬영하거나 공개하지 않습니다.
- 화면 하나는 대략 260~280px, 비교가 필요한 두세 화면은 230~260px 너비로 배치합니다. 이미지에는 내용을 설명하는 `alt`와 원본을 여는 링크를 넣습니다.
- 세로 화면·다크모드·키보드·설정 등은 설명에 필요한 만큼 사용합니다. 사진 수를 임의의 고정 숫자로 제한하거나 모든 캡처를 README에 넣을 필요는 없습니다.
- 자세한 화면 모음과 촬영 버전·OS·대체한 업데이트 응답 등의 조건은 [화면 안내](화면-안내.md)에 정리합니다. 새 버전의 화면으로 바뀌면 촬영 정보도 갱신합니다.
- 실제 PNG는 [docs/screenshots](screenshots/)에 보관합니다. `design/`의 디자인 시안을 실행 화면이나 검증 근거로 사용하지 않습니다.
- UI가 그대로인 화면은 재사용할 수 있습니다. 바뀐 화면은 새로 확인·촬영하고 README와 화면 안내의 설명·링크도 맞춥니다. 파일 이름만으로 최신 화면이라고 판단하지 않습니다.

촬영 방법은 [개발 안내](개발-안내.md)의 문서용 실행 화면 촬영 절을 따릅니다. 촬영 스크립트는 선택한 에뮬레이터의 개발용 앱 데이터를 초기화하므로 **초기화해도 되는 촬영 전용 에뮬레이터**에서만 실행합니다. 사용자가 직접 테스트 중인 에뮬레이터에는 실행하지 않습니다.

캡처 목록은 [촬영 코드](capture/DocumentationCapture.kt)와 실제 생성된 PNG를 확인합니다. 수동으로 촬영한 화면도 별도로 확인하며, 이전 문서의 고정 장수를 그대로 사용하지 않습니다.

## 5. 버전 정보와 다른 문서의 역할

새 릴리즈에서는 README의 실제 사용 방법을 갱신합니다. 제목을 특정 버전으로 바꾸거나 본문을 ‘이번 버전의 변경 사항’으로 대체하지 않습니다. 사용자에게 필요한 호환성 조건은 해당 사용 단계에서 설명할 수 있습니다.

| 내용 | 둘 위치 |
| --- | --- |
| 설치·설정·기록·재고·백업·업데이트 사용법 | 루트 [README](../README.md) |
| 텍스트로 빠르게 확인하는 사용법 | [사용 안내](사용-안내.md) |
| 전체 실행 화면과 촬영 조건 | [화면 안내](화면-안내.md) |
| 버전별 새 기능·변경 사항·알려진 제한 | `docs/releases/vVERSION.md`와 GitHub 릴리즈 노트 |
| 실제 검사 결과·커밋·해시·확인 범위 | [검증 기록](검증-기록.md)과 해당 릴리즈의 검증 자료 |
| 빌드·테스트·촬영 명령과 구현 구조 | [개발 안내](개발-안내.md) |
| 릴리즈 검증·서명·배포·실패 재개 | [로컬 검증 후 배포 운영 가이드](로컬-검증-후-배포-운영-가이드.md) |

검사 개수·APK 해시·CI 실행 시간·빌드 커밋·개발용 설정을 사용자 조작 설명에 섞지 않습니다. README와 보조 문서에 같은 사용법이 있으면 함께 수정해 서로 다른 안내가 남지 않게 합니다.

## 6. 수정과 확인 순서

1. 변경된 기능의 실제 화면·버튼·동작과 현재 README를 확인합니다.
2. 기본 구성에서 해당하는 절을 수정합니다. 새 사용 절차가 필요하면 목차에도 반영합니다.
3. 필요한 화면만 교체·추가하고, 사용 안내·화면 안내·문서 모음의 관련 내용도 맞춥니다.
4. 아래 확인 목록과 `git diff --check`로 문서 변경을 점검합니다. Markdown 미리보기에서 표·이미지·목차가 읽기 쉬운지도 확인합니다.
5. 실제 수행한 확인만 결과로 남기고, 요청 범위에 따라 커밋·푸시합니다. 릴리즈 작업이면 운영 가이드의 문서 마무리와 커밋 관계 확인을 이어서 수행합니다.

### 완료 전 확인 목록

- [ ] 제목·소개·다운로드가 특정 버전에 고정되지 않았습니다.
- [ ] 처음 사용하는 분이 README만으로 기본 사용 순서를 따라 할 수 있습니다.
- [ ] 메뉴·버튼 이름, 입력 단위, 저장 결과가 현재 앱과 맞습니다.
- [ ] 날짜·초안·재고 차감·삭제·복원·업데이트 설명에 빠진 중요한 조건이 없습니다.
- [ ] 목차 앵커·상대 링크·이미지 경로가 유효하며 이미지 설명과 화면이 일치합니다.
- [ ] 화면의 개인 정보·실제 사용자 데이터 노출이 없고, 촬영 조건은 화면 안내에 기록했습니다.
- [ ] 사용 안내·화면 안내·문서 모음의 관련 내용도 일치합니다.
- [ ] 버전별 변경 내용과 검증 결과는 해당 문서에 남겼습니다.
- [ ] `git diff --check`를 통과했습니다.

문구·링크·배치만 바꾼 경우에는 문서에 필요한 로컬 확인을 수행합니다. README 수정 때문에 APK 재빌드, 전체 E2E, 원격 Android Actions를 반복하지 않습니다. 앱·빌드·검사 코드도 바뀌었다면 그 변경에 필요한 검사를 별도로 수행하며, `docs/capture/`의 Kotlin 코드는 문서만의 변경으로 취급하지 않습니다. **GitHub Actions의 반복 실패와 긴 대기를 줄이는 릴리즈 운영 목적을 유지합니다.**
