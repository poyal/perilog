# 자동 E2E 테스트

실제 앱의 Compose 화면을 누르고 입력한 뒤 Room에 저장된 결과와 재고 잔량을 확인합니다. 외부 API·가짜 서버는 사용하지 않습니다. 테스트 자료는 개발용 패키지 `com.poyal.perilog.debug`에만 넣습니다.

릴리즈 검증에서는 [운영 가이드](release.md)의 API·글씨 배율·예상 테스트 목록·실패/생략 기준을 적용합니다. 이 문서의 부분 검사 명령은 전체 릴리즈 검사를 대신하지 않습니다. 서명 APK 신규 설치·업데이트 데이터 보존 검사는 별도로 수행합니다.

## 실행

개발용 에뮬레이터와 JDK 17, Android SDK 36을 준비합니다. `.tools/`의 로컬 도구가 있으면 빌드 스크립트가 우선 사용합니다.

```sh
# 계산·재고·백업 규칙 및 Android 정적 검사
./scripts/build.sh :app:testDebugUnitTest :app:lintDebug

# 기본 글씨 / 글씨 1.5배 / 두 가지 모두
PERILOG_SERIAL=emulator-5554 ./scripts/test-e2e.sh normal
PERILOG_SERIAL=emulator-5554 ./scripts/test-e2e.sh large
PERILOG_SERIAL=emulator-5554 ./scripts/test-e2e.sh all

# 실제 백그라운드 프로세스 종료 후 미저장 입력 복구
PERILOG_SERIAL=emulator-5554 ./scripts/test-process-restore.py
```

스크립트는 개인 기기 연결을 거부하고 `emulator-*`만 허용합니다. 실행마다 개발용 앱 자료를 초기화하고 비행기 모드를 켭니다. 가상 하드웨어 키보드가 연결돼 있어도 화면 키보드를 표시하도록 설정합니다. 화면을 깨우고 기본 잠금 화면을 해제하며 검사 중에는 화면이 꺼지지 않게 합니다. 종료 시 원래 글자 크기·비행기 모드·키보드·화면 시간 제한·충전 중 화면 유지 설정을 복구합니다. 사용 중인 개발용 자료가 있으면 먼저 별도 보관하세요. 테스트 실행 중 에뮬레이터를 직접 조작하거나 다른 앱을 실행하지 않습니다.

## 검증 범위

`SettingsFlowTest`는 설정 첫 화면의 모든 항목 직접 진입·한 번 뒤로 가기·스크롤 위치 복원과 데이터 불변, 미저장 변경 확인·화면 재생성, 저장 후 요약 갱신, 영역별 독립 저장, 잘못된 입력 보존, OS 알림 설정·파일 선택기 취소 복귀, 가로 화면의 저장 접근성, 이전 축하 설정이 있어도 완료 화면에서 효과·표시 이력 저장이 없는 것을 확인합니다. `UsabilityFlowTest`는 설정별 완료 안내, 기록의 원터치 구성 선택과 조정 수량 보존, 치료 항목 시간 저장·해제를 검사합니다.

`ReplenishmentFlowTest`는 기록 없는 주간 구성의 나머지 일수·저장, 직접 수량의 도움말 왕복·화면 재생성·입력 오류 수정, 선택한 품목만 분할 입고, 오프라인 안내 검색·이미지 확대·미저장 품목 보존을 검사합니다. 직접 사용량은 다크 모드 가로 회전과 도움말 왕복 후 계산·재고 불변까지 확인합니다. 기본 E2E 대상에도 포함됩니다. 계산 단위 검사는 확정 일수·빈 날 제외·분수 올림·날짜별 사용 변경·당일 사용·미등록 재고·방문 전 부족·수동 수정·저장 기준 보존을, 저장소 검사는 분할 입고 수정·취소·백업 호환·트랜잭션 실패와 7→8 이전을 확인합니다.

연락처 번호 입력은 `AppointmentFlowTest`의 `contactPhoneAcceptsSpacesHyphensAndShortNumbers`, `contactPhoneMiddleEditingAndBackspaceKeepDigitsAndCursor`에서 숫자·공백·하이픈 입력, 대표번호와 114 등 짧은 번호, 중간 선택·교체·삭제, 화면 재생성 후 유지와 저장을 확인합니다. `PhoneNumberInputTest`는 API 31·35에서 표시 형식과 숫자 보존을, `ContactIntentTest`는 전화·문자 연결 대상을 검사합니다.

병원 일정 기능의 화면 검사는 `AppointmentFlowTest`에서 설정 목록의 병원·연락처 구역, 진료과 다중 선택·색상·서로 다른 예약시간·이름과 시간 태그, 시간 누락·잘못된 입력 차단과 진료과별 시간 선택, 개별 치료 항목 등록·아이콘·복수 선택, 예약 재사용·수정·삭제, 연락처 이모지·전화/문자 허용, 홈 아바타 한 줄 3개 배치와 연결 방법 모달을 확인합니다. 홈 +에서 빈 새 예약 진입, 등록 후 홈 관리 버튼 숨김, 두 연결 방법을 모두 끈 연락처, 작성 중 관리 화면 이동·화면 재생성, 진료과별 시간의 파일 백업·복원, 다크 모드와 추가투석 기록 진입도 확인합니다. 같은 날 진료시간 경계와 이전 공통 시간의 보존은 단위 검사로 확인합니다. 테스트는 별도 초기화 가능한 에뮬레이터에서 실행하며 스크린샷을 촬영하거나 전화·문자를 보내지 않습니다. 수신 번호와 Intent 형식은 단위 검사로 확인합니다.

캘린더 연동은 기본 검사에 포함한 `CalendarFlowTest`에서 테스트 전용 LOCAL 캘린더와 샘플 예약으로 생성·수정·삭제, 외부 변경 무시, 기존 알림·무관한 일정 보존, 연결 식별자 손실과 쓰기 권한 상실을 확인합니다. 이 클래스는 안내용 실행 화면을 앱 내부 `files/calendar-screenshots`에 보관합니다. OS 권한 거절은 권한을 미리 해제한 뒤 별도의 `CalendarPermissionFlowTest`로 확인합니다. 구체적 명령과 실제 서비스 검증의 남은 항목은 [캘린더 연동 검증](구글-캘린더-연결-준비.md)에 있습니다.

수동 테스트를 위해 에뮬레이터를 열 때는 샘플 데이터도 함께 준비합니다. `-PcaptureScreenshots`로 앱·androidTest APK를 빌드하고 설치한 뒤 `com.poyal.perilog.capture.PreviewSamples#load`만 실행합니다. 물품 6개, 구성 2개, 입고 재고와 지난 2주·오늘·추가투석 예시를 추가하며 기존 입력과 수정값은 보존합니다. 연락처 예시가 필요하면 `com.poyal.perilog.capture.PreviewSamples#loadContacts`를 따로 실행합니다. 투석실·고객센터·간호사 샘플을 추가하며 반복 실행 시 기존 연락처와 샘플 수정값을 유지합니다. 준비가 끝나면 앱을 다시 열어 둡니다. 전체 E2E 실행은 별도의 검증 작업입니다.

한 달이 넘는 샘플이 필요하면 같은 `PreviewSamples#load` 실행에 `-e historyDays 42`를 추가합니다. 14~180일을 지정할 수 있고 기본값은 14일입니다. 14일을 넘기면 샘플 투석액의 다양한 사용 예시도 포함하며, 기존 날짜의 기록·수정값·초안은 유지합니다. 과거 사용 기록 추가로 기존 현재 재고가 줄어들지 않도록 순증 사용량에 대응하는 샘플 입고를 추가하고, 적용 전후 재고와 기존 값 보존을 확인합니다. 같은 날짜·기간으로 반복 실행해도 중복 기록·입고를 추가하지 않습니다.

## 결과 및 CI

각 실행의 HTML/XML 결과, 전체 실행 로그, Android 로그와 실패 화면은 `.tools/e2e-results/normal/` 또는 `large/`에 저장됩니다. Git에는 예시 사용자 자료를 담은 보고서를 커밋하지 않습니다.

`.github/workflows/test.yml`은 **수동 진단 전용**입니다. main·PR 푸시로 자동 실행하지 않습니다. 원격 러너의 환경 차이를 확인해야 할 때만 Actions의 Run workflow로 단위·Lint·API 35 기본/큰 글씨 E2E·프로세스 복구를 실행하고 보고서를 14일 보관합니다. 일반 릴리즈는 로컬 검증으로 진행하며 같은 검사를 원격에서 다시 통과할 필요가 없습니다. 이 진단 작업은 APK를 배포하거나 릴리즈를 게시하지 않습니다.

프로세스 복구 스크립트는 새 품목 폼에 임시 이름을 입력하고 홈으로 이동합니다. Activity가 `STOPPED`이며 Android가 상태를 저장한 것을 확인한 뒤, 개발용 앱 UID의 `run-as`로 해당 PID만 종료합니다. 기존 PID가 사라질 때까지 제한 시간 안에서 확인합니다. 새 PID에서 미저장 내용을 확인한 뒤 버리므로 품목을 저장하지 않습니다. 결과는 `.tools/e2e-results/process/`에 남습니다.

GitHub에서의 실제 실행 여부는 로컬 통과와 구분해 기록합니다. Android 15의 창 재생성 오류를 확인하기 위해 로컬에도 API 35 / Pixel 7 에뮬레이터를 추가했습니다. CI와 같은 API에서 수정 전 실패를 재현하고, API 35·36의 기본/큰 글씨에서 수정 후 회전 검사를 확인합니다.

CI는 Android SDK 도구를 설치한 뒤 플랫폼·시스템 이미지 설치, AVD 생성, 부팅을 나눠 실행합니다. `ANDROID_USER_HOME`·`ANDROID_EMULATOR_HOME`·`ANDROID_AVD_HOME`을 러너 임시 디렉터리로 통일해 생성한 기기를 같은 경로에서 찾습니다. 부팅은 180초로 제한하고, 프로세스가 종료되면 즉시 실패합니다. 실패 로그 마지막 30줄은 Actions 요약에도 남깁니다. 환경변수 역할은 [Android 공식 문서](https://developer.android.com/tools/variables)를 참고하세요.

`am kill`은 Android가 종료해도 된다고 판단하는 프로세스만 대상으로 하므로 호출 직후 종료를 보장하지 않습니다([공식 설명](https://developer.android.com/tools/adb#am)). 복구 검사는 저장된 task를 유지한 실제 프로세스 사망을 재현하며, 종료 성공·새 PID·미저장 입력 복구를 각각 확인합니다. 실패 시 고정된 단계 이름과 오류 종류만 CI annotation에 표시하고, 화면 자료 수집 실패가 원래 오류를 덮지 않도록 했습니다.

회전·키보드 검사는 Activity 창 포커스를 기다리고 화면 키보드를 요청한 뒤 실제 IME inset 표시를 확인합니다. 회전·키보드 같은 OS 전환은 최대 30초 동안 기다리며 조건 이름과 화면 켜짐·잠금·창 포커스 여부를 오류에 남깁니다. 입력칸의 95% 이상 표시, 저장 버튼, 61.5 값 보존과 재고 불변을 계속 검사합니다. 회전 후 원래 방향 설정도 복구합니다.

Compose의 idle 대기만으로 시스템 키보드 애니메이션이 끝났다고 판단하지 않습니다. 입고 저장 검사는 키보드 표시와 저장 버튼의 위치가 안정된 후 실제 터치합니다. 병원 일정·설정 검사의 입력 도구는 키보드 숨김과 접근성 이벤트의 안정화를 기다린 뒤 다음 버튼을 누릅니다. 외부 파일 선택기나 OS 설정에서 돌아올 때는 앱 창의 포커스를 확인하여 닫히는 화면에 뒤로 가기를 중복 전달하지 않습니다. 저장 결과는 계속 실제 DB 값으로 확인하며, 터치가 빗나간 시간 초과를 저장 성공으로 처리하지 않습니다.

사용 구성·입고 초안 재생성 검사는 재생성 전에 입력값을 확인하고 Compose 상태 반영을 기다립니다. 입고는 저장 가능 상태도 확인한 뒤 Activity를 재생성하며, 복원된 값과 기존 재고 불변을 별도로 확인합니다.

CI는 긴 빌드 중에도 화면이 잠들지 않도록 부팅 직후 화면 유지 설정을 적용합니다. E2E와 프로세스 복구 스크립트도 각자 화면을 깨우고 잠금을 해제하므로 단독 실행이 가능합니다. 프로세스 복구 스크립트는 종료 시 원래 화면 설정을 복구합니다. 비밀번호가 설정되지 않은 개발용 에뮬레이터를 사용합니다.

개발 중에는 수정한 기능과 실패한 시나리오부터 검사합니다. 특정 검사만 재현할 때는 전체 결과를 덮지 않도록 별도 결과 폴더를 지정합니다. 확정된 릴리즈 후보의 전체 검증은 한 번 수행하고, 검증 후 동일 APK를 게시할 때 재빌드하거나 원격 전체 검사를 반복하지 않습니다. 테스트 추가·변경 시 `AppFlowTest`·`AppointmentFlowTest` 등 현재 소스의 실제 목록과 실행 결과를 대조합니다.

```sh
PERILOG_TEST_TARGET='com.poyal.perilog.AppFlowTest#typedDraftSurvivesActivityRecreationRotationAndDoesNotConsumeStock' \
PERILOG_RESULTS_DIR="$PWD/.tools/e2e-ime-check" \
./scripts/test-e2e.sh all
```

## 위젯과 연락처 순서 검사

`StockForecastFlowTest`는 홈에서 부족 예상일 때만 나타나는 시간 옆 아이콘과 상세 이동, 충분·0·미확인 상태의 숨김, 일정 관리의 추세 설명·품목별 잔량·실제 재고 조정 후 재계산·공통 사용 패턴·도움말과 재생성 후 복구를 검사합니다. `ReplenishmentFlowTest`에는 여유 일수와 품목별 추가분, 잘못된 소수 입력, 최종 직접 지정 유지와 자동 계산 복귀를 포함합니다. `AppFlowTest`의 기록 표 검사는 조작 영역이 실제 표 위에 있는지도 확인합니다.

출시 APK의 위젯 종류·프로세스 종료·업데이트 회귀는 [위젯 개발 가이드](위젯-개발-가이드.md)의 별도 테스트 호스트를 사용합니다. 같은 프로세스에서 위젯 하나를 검사한 결과로 이 검사를 대신하지 않습니다.

`WidgetFlowTest`는 실제 `AppWidgetHost`에 위젯을 연결하여 RemoteViews의 내용과 클릭을 검사합니다. 어제·오늘의 세 단계, 기록 열기만으로 사용량이 바뀌지 않는 동작, 앱 잠금 시에도 위젯 표시 유지, 진료과별 예약시간과 삭제된 예약의 목록 이동, 다른 목적지로 이동할 때 미저장 변경 확인·폐기, 같은 기록 위젯 재선택 시 입력 유지와 화면 재생성을 확인합니다. 입력 중 새 DB 초안은 만들지 않으며 도움말에서 돌아오는 경로와 잘못된 숫자 입력도 검사합니다. 연락처는 저장 전 DB 불변, 순서 저장·취소, 도움말 왕복·재생성, 홈의 표시 순서를 확인합니다.

크기 적응 검사는 110×110·148×156·158×172·146×274·303×274·328×172·382×274·265×135dp를 라이트·다크 실제 View로 확인합니다. 별도 회전 검사에서 542×135·681×135dp를 검증하고 시스템 테마의 글자색 전환도 확인합니다. 글자의 줄임표·높이/너비 잘림·스크롤, 처치 누락, 긴 2×2의 한 열 배치와 아래쪽 과도한 공백을 검사합니다. 긴 이름·홀수 항목·이전 치료 구성은 1·5·12개 예시로 확인합니다. 픽셀 밀도에 따른 측정과 배치 경계는 `WidgetLayoutTest`에서 검사합니다. 4×1 검사는 303×131·276×102·328×80·303×48dp와 더 좁은 110×48·146×80dp에서 날짜별 아이콘의 가로 정렬과 모든 텍스트 표시를 확인하며, 가로 회전 시 542×51·681×51dp도 검사합니다. 실제 런처의 4×2↔4×1 크기 조절·미리보기·배치는 별도 수동 확인합니다.

검사 호스트의 위젯 바인딩 권한은 테스트 기기에만 부여합니다. 검사 종료 시 호스트와 위젯을 삭제합니다. 사용자가 직접 기록하는 에뮬레이터에는 실행하지 않습니다. 날짜 경계·추가투석과 세 단계 판정은 `WidgetDataTest`, 순서의 백업·복원과 설정 저장 후 유지 여부는 `RepositoryTest`로 함께 확인합니다.

```sh
PERILOG_SERIAL=emulator-5560 PERILOG_TEST_TARGET=com.poyal.perilog.WidgetFlowTest \
PERILOG_RESULTS_DIR="$PWD/.tools/widget-e2e" ./scripts/test-e2e.sh all
```

## 업데이트 다운로드와 설치 연결

`./scripts/test-updates.sh`는 `-PupdateFixture`로만 포함되는 `src/updateTest` 검사입니다. 기기 루프백 서버가 작은 개발 서명 APK를 제공하고 실제 DownloadManager·FileProvider·Android 설치 화면·취소 후 파일 보존·변조 거부를 검사합니다. 기본 UI 검사에는 포함하지 않습니다. 설치 출처 권한을 끄면 Android가 앱을 종료하므로 검사 종료 후 호스트에서 원복합니다.

버전 판정·조회 캐시·다운로드 복구·체크섬과 색상 대비는 로컬 단위 검사에서 확인합니다. 모든 일반 UI 검사는 GitHub 응답을 대체하므로 네트워크에 의존하지 않습니다.

## 지원 범위와 변경

- 1.0.15부터 Android 11(API 30) 이상을 지원합니다. 직전 공개 APK 1.0.14는 Android 12(API 31) 이상입니다.
- 아래 검증한 개발 후보의 Android 11 지원을 1.0.15에 반영했습니다. 1.0.15의 실제 릴리즈 검사 결과는 [검증 기록](releases/v1.0.16/AGENTS.md)을 확인하세요. 아래 arm64 에뮬레이터 검사 범위에서 호환성 검증을 완료했습니다. `compileSdk`·`targetSdk`는 36을 유지합니다.
- Android 10(API 29)은 사용자 승인에 따라 앱 잠금만 제외하는 후보까지 구현해 조사했습니다. 집중 검사는 기본·큰 글씨 각각 4개 통과했지만 전체 기본 글씨 84개 중 6개가 실패했습니다. 키보드 복귀 2건, 1,000행 표의 메모리 부족, 연락처 조작, 위젯 시스템 테마, 녹화 파일 생성 문제입니다. API 29 이미지의 앱 힙 제한은 48MB, API 30은 192MB였습니다. 모든 실패를 앱 결함으로 단정하지 않지만 추가 환경·동작 대응이 필요하므로 이번 저비용 지원 범위에서는 제외했습니다. 이 조사 후보의 기능 분기는 최종 소스에 남기지 않았습니다.
- Android 11 이상에서는 앱 잠금·화면 보호를 모두 유지합니다. `BIOMETRIC_STRONG | DEVICE_CREDENTIAL` 인증 조합을 변경하지 않습니다. [AndroidX 인증 지원 범위](https://developer.android.com/reference/androidx/biometric/BiometricPrompt.PromptInfo.Builder)
- Android 11의 API 제약은 수량 계산의 `BigInteger.longValueExact()`와 위젯의 시스템 모서리 리소스입니다. 수량은 범위를 확인한 뒤 변환하여 넘침 예외를 보존하고, 위젯은 Android 11의 로컬 치수와 Android 12 이상의 기존 시스템 치수를 사용합니다. 큰 글씨 가로 위젯에서 제목 행이 과도한 높이를 차지하던 Android 11 문제도 수정했습니다. 큰 가로 키보드로 앱의 세로 공간이 180dp보다 작아지면 공통 페이지의 저장 영역을 옆으로 옮겨 입력란을 확보합니다. 버튼 규격과 입력 컴포넌트의 상태는 유지합니다. 라이브러리 다운그레이드·DB 이전·백업 형식 변경은 없습니다.

밝게·어둡게, 회전, 입력·저장·키보드, 초안, 재고, 일정, 잠금·화면 보호, 위젯을 기존 UI 검사로 확인합니다. 실제 파일 선택기의 가져오기·내보내기·백업 폴더 연결과 OS 알림 허용·거절·철회는 서명 APK를 조작하는 호스트 검사로 확인합니다. Google 실제 계정 OAuth·웹 반영, 제조사 키보드, 실제 생체 센서, 폴더블 힌지, 장시간 제조사 절전은 별도 실기기·서비스 미검증 범위입니다.

## 로컬 실행

JDK 17과 프로젝트 `.tools/android-sdk`를 사용합니다. `sdkmanager`로 각 API의 `google_apis;arm64-v8a` 이미지를 설치합니다. API 37은 `android-37.0`, 16KB 이미지는 `google_apis_ps16k`입니다. 베타·Canary 이미지를 정식 OS 결과에 섞지 않습니다.

API 37은 Command-line Tools 20 이상과 에뮬레이터 메모리 4GB를 사용합니다. 구형 도구 19는 `37.0`을 API 0으로 잘못 기록하여 하드웨어 가속 없이 부팅에 실패할 수 있습니다. 실행기는 설치된 안정 도구 중 가장 최신 것을 선택하고, 전용 AVD의 이미지 경로가 일치할 때만 잘못된 메타데이터를 원본 보관 후 고칩니다. 이번 실행에는 도구 23.0·Emulator 37.1.11을 사용했습니다. [공식 Emulator 변경 기록](https://developer.android.com/studio/releases/emulator)

```sh
./scripts/build.sh :app:testDebugUnitTest :app:lintDebug :app:lintRelease \
  :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease \
  :widget-test-host:assembleDebug -PwidgetHost

python3 scripts/compatibility-emulator.py start --api 30
python3 scripts/test-compatibility.py \
  --serial emulator-5590 --avd perilog_compat_api30 --api 30 \
  --suite full --output .tools/compatibility/실행ID/api30-full \
  --apk .tools/compatibility/실행ID/artifacts/debug.apk \
  --test-apk .tools/compatibility/실행ID/artifacts/tests.apk
python3 scripts/compatibility-emulator.py stop --api 30
```

빌드 후 APK를 실행별 `artifacts/`에 복사하여 해시를 고정한 다음 위 명령의 경로를 사용합니다. `실행ID`는 실제 새 폴더 이름으로 바꿉니다. 같은 결과 폴더를 재사용하면 검사기가 거부합니다. 실패 자료는 유지하고 수정·재시도에는 새 폴더를 사용합니다. 앱이나 APK가 바뀌면 이전 결과를 새 후보의 통과로 합치지 않습니다.

- `--suite core`: 중간 OS의 핵심 회귀입니다.
- `--suite permissions --profile normal`: 사전 권한이 없는 가상 앱에서 캘린더 거절을 검사합니다.
- `--suite layout --layout tablet`: 태블릿 크기의 화면·위젯을 기본·큰 글씨에서 확인합니다. `--layout compact`는 폭 360dp입니다. 원래 화면 크기·밀도는 종료 시 복구합니다.
- `scripts/test-compatibility-window.py --serial <시리얼> --avd <전용 AVD 이름> --apk <고정한 개발 APK> --output <새 결과 폴더>`: 설치 파일 해시를 확인하고 실제 freeform 작업 창을 넓게→좁게→넓게 바꾸면서 미저장 입력 보존과 취소를 확인합니다. 작업 창의 요청 좌표와 실제 좌표를 대조하며, 제목 표시줄이 차지하는 공간은 앱 화면 좌표와 구분합니다. 앱의 실제 폭·높이가 줄어들었다가 원래 크기로 돌아오는지도 검사합니다. 폴더블 힌지 검증을 대신하지 않습니다.
- `--page-size 16384`로 기기를 시작하면 AVD 이름에 `_16k`가 붙습니다. 실제 `getconf PAGE_SIZE`가 16384가 아니면 부팅 확인을 통과하지 않습니다.
- `PERILOG_PROCESS_RESULTS_DIR`로 `scripts/test-process-restore.py`의 결과 위치를 실행별로 지정할 수 있습니다. 결과에서 실제 PID 교체와 초안 복구를 확인합니다. API 30은 `run-as`의 프로세스 종료를 SELinux가 막으므로 전용 `perilog_compat_` 테스트 이미지에서만 ADB root를 사용합니다. 중지된 Activity의 저장 상태와 PID를 다시 확인한 뒤 그 프로세스만 종료하며, `force-stop`이나 앱 데이터 초기화로 대체하지 않습니다.

서명 APK 검사는 다음 명령을 사용합니다. `--previous-apk`를 추가하면 기존 앱에 가상 자료를 넣은 뒤 삭제 없이 후보를 덮어 설치합니다. 이전 APK의 minSdk가 검사 OS보다 높으면 업그레이드는 해당 없음으로 기록하고 신규 설치·백업 복원을 확인합니다.

```sh
python3 scripts/test-compatibility-system.py \
  --serial emulator-5590 --avd perilog_compat_api30 \
  --apk .tools/compatibility/실행ID/artifacts/release.apk \
  --output .tools/compatibility/실행ID/api30-system
python3 scripts/check-apk-pages.py .tools/compatibility/실행ID/artifacts/release.apk \
  --output .tools/compatibility/실행ID/page-alignment.json
```

검사기는 이름이 `perilog_compat_`로 시작하며 지정한 이름과 일치하는 전용 에뮬레이터만 허용합니다. UI 검사는 그 기기의 개발 앱 자료를 초기화합니다. 서명 APK 검사는 기존 설치가 있으면 중단하며, 해당 전용 기기의 합성 자료임을 확인한 재시도만 `--reset-fixture`를 지정합니다. 기존 개발·미리보기 AVD와 사용자 실제 자료는 대상이 아닙니다.

## 판정과 근거

명령 종료 코드만으로 성공을 판단하지 않습니다. UI 검사에는 예상 테스트 이름 전체의 종료 결과, JUnit 성공 요약, 정상 instrumentation 종료가 모두 필요합니다. 실패·오류·생략·중복·누락·중단·보고서 부재는 실패입니다. 실행기는 미완료 검사를 통과로 만들지 않으며 Gradle 재빌드 없이 지정 APK만 설치합니다.

테스트 전용 Espresso는 3.7.0을 명시합니다. Compose의 간접 의존성 3.5.0은 Android 17에서 제거된 내부 메서드를 호출해 앱 조작 전에 실패했습니다. 시스템 인증 창은 실제 PIN으로 확인하며, Android 17의 새 숫자 키패드도 직접 조작합니다. 테스트 APK를 보완한 경우 별도 파일·해시·소스 기록을 남기고, 앱 APK의 바이트가 그대로인지를 확인합니다. [공식 AndroidX Test 버전](https://developer.android.com/jetpack/androidx/releases/test)

서명 APK 검사는 설치된 `base.apk`와 고정 파일의 바이트, 기존 인증서, 신규 설치·복원, DB 무결성·모든 기존 필드, UID·최초 설치 시각, 초안·설정, 보호 백업, 실제 SAF 권한과 폴더 재선택 없는 새 백업을 확인합니다. DataStore의 업데이트 조회 메타데이터만 비교에서 제외합니다. 새 백업 JSON의 생성 시각 외 값은 동일해야 합니다.

16KB 정적 검사는 APK ZIP 정렬과 모든 64비트 네이티브 라이브러리의 ELF 적재 구간을 검사합니다. 32비트 라이브러리는 별도로 보고하며 16KB 런타임의 대상으로 간주하지 않습니다. 정적 통과는 실제 16KB 실행 검사를 대신하지 않습니다. [Android 16KB 지원 안내](https://developer.android.com/guide/practices/page-sizes)

검사 로그·JUnit XML·실패 화면·가상 자료는 `.tools/compatibility/<실행ID>/`에 보관하고 공개 문서에는 결과와 출처만 남깁니다. GitHub Actions는 기존처럼 수동 진단 전용을 유지합니다. 이번 후보를 릴리즈로 게시하려면 별도로 [로컬 검증·배포 운영 가이드](release.md)를 따라야 합니다.
