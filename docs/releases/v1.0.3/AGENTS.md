### v1.0.2→v1.0.3 전체 데이터 보존 추가 검증

2026-10-02, 공개 APK 두 개를 새로 내려받아 별도 Android 15 / API 35 arm64 에뮬레이터에서 검사했습니다. 실제 사용자 자료는 사용하지 않았습니다. 구버전의 백업 가져오기 UI로 가상 자료를 채우고 실제 파일 선택기로 백업 폴더를 연결한 뒤, 앱 삭제·초기화 없이 공개 v1.0.3 APK를 `install -r`로 설치했습니다.

- 9개 테이블의 **48행·기존 필드 값 500개 모두 일치**: 기록 13, 사용 내역 14, 물품 6, 구성 3, 입고 3, 재고 실사 2, 감사 이력 4, 초안 2, 설정 1.
- DB 1→3 이전과 SQLite 무결성 검사 통과. 새 컬럼만 계획한 기본값으로 추가됐으며 앱 UID와 최초 설치 시각이 유지됐습니다.
- 음수·0·미입력, mL·g·kg, 과거 계산 기준, 취소 이력, 비활성 품목, 삭제 기록의 사용 내역, 미저장·수정 중 초안과 비기본 설정을 보존했습니다.
- 재고 화면의 5개 품목 수량이 전후 `38 / 100 / 107 / 91 / 22 EA`로 동일했습니다.
- DataStore와 내부 보호 백업 파일 해시, 백업 폴더 영구 읽기·쓰기 권한, 알림 권한이 유지됐습니다. 폴더 재연결 없이 새 백업 생성에 성공했고 기존 백업도 보존됐습니다.
- 두 버전이 만든 전체 백업 JSON은 생성 시각과 v1.0.3 신규 필드만 제외하면 모두 동일했습니다.

원본 비교·스크립트·가상 DB·화면은 로컬 `.tools/upgrade-full-audit/`의 `RESULT.txt`, `comparison.json`, `export-comparison.json`, `before/`, `after/` 등에 보관합니다. `.tools/`는 Git 제외 경로이므로 이 자료가 새 체크아웃에도 있다고 가정하지 않습니다. 이 검증은 공개 APK의 에뮬레이터 결과이며 사용자 실기기 검사를 대신하지 않습니다.
