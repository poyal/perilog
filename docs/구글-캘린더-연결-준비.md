# 구글 캘린더 직접 연결 준비

이 문서는 페리로그 배포자가 한 번 준비하는 Google Cloud 설정입니다. 일반 사용자는 앱에서 계정과 캘린더를 선택합니다. 휴대폰 캘린더 연결은 이 Cloud 설정을 사용하지 않습니다.

현재 저장소에는 `AuthorizationClient`를 통한 계정 권한 요청과 Calendar REST API 전송 코드가 있습니다. **Google Cloud 프로젝트와 실제 테스트 계정은 아직 준비되지 않았으며, 실제 구글 로그인·전송은 검증하지 않았습니다.** 설정 완료 전에는 구글 직접 연결을 사용 가능하다고 안내하지 마세요.

## 1. 프로젝트와 Calendar API

1. [Google Cloud Console](https://console.cloud.google.com/)에서 이 앱을 관리할 프로젝트를 만듭니다. 프로젝트 ID를 따로 기록합니다.
2. **API 및 서비스 → 라이브러리 → Google Calendar API**에서 API를 사용 설정합니다.
3. **Google Auth Platform → Branding**에 앱 이름, 지원 이메일, 홈페이지와 개인정보처리방침 주소를 등록합니다. 개인정보처리방침에는 사용자가 연결한 병원 일정 정보와 선택적 메모가 선택한 캘린더로 전송된다는 점을 포함합니다.
4. **Audience**에서 개인 구글 계정을 사용하는 경우 External로 설정하고, 개발 중에는 Testing 상태에서 테스트 전용 계정을 추가합니다. 검사에는 가상 예약만 사용합니다.

설정 항목과 OAuth 준비 절차는 [Google Calendar 권한 안내](https://developers.google.com/workspace/calendar/api/auth)와 [Android Google 인증 안내](https://developer.android.com/identity/authorization)를 참고합니다.

## 2. 필요한 권한

**Data Access**에 다음 두 권한을 등록합니다. 앱도 같은 권한만 요청합니다.

| 권한 | 용도 |
| --- | --- |
| `https://www.googleapis.com/auth/calendar.calendarlist.readonly` | 사용자가 선택할 수 있는 캘린더 목록 조회 |
| `https://www.googleapis.com/auth/calendar.events` | 선택한 캘린더의 페리로그 일정 생성·수정·삭제 및 기존 연결 확인 |

앱은 쓰기 가능한 캘린더 하나만 연결하며, 자체 연결 식별자가 일치하는 일정만 변경합니다. 캘린더 데이터를 병원 예약으로 가져오는 기능은 없습니다. 권한 이름과 허용 범위는 [공식 scope 목록](https://developers.google.com/workspace/calendar/api/auth)에 있습니다.

## 3. Android OAuth 클라이언트

**Clients → Create client → Android**에서 패키지명과 해당 APK의 서명 인증서 SHA-1을 등록합니다. 디버그와 배포용은 각각 등록합니다.

| 종류 | 패키지명 | 등록할 인증서 |
| --- | --- | --- |
| 개발 검사 | `com.poyal.perilog.debug` | 이 개발 환경에서 만든 debug APK의 서명 인증서 |
| 실제 배포 | `com.poyal.perilog` | 기존 페리로그 배포 서명 키의 인증서 |

개발 APK는 프로젝트 루트에서 다음으로 만듭니다.

```sh
./scripts/build.sh :app:assembleDebug
.tools/android-sdk/build-tools/36.0.0/apksigner verify --print-certs app/build/outputs/apk/debug/app-debug.apk
```

`Signer #1 certificate SHA-1 digest` 값을 사용합니다. 배포용은 **이미 기존 키로 서명된 APK**를 같은 `apksigner verify --print-certs` 명령에 넣어 확인합니다. 캘린더 설정을 위해 서명 키를 새로 만들거나 바꾸지 않습니다. 서명 키·비밀번호·백업 ZIP을 Google Console에 업로드하지 않습니다.

이 구현은 Android `AuthorizationClient`에서 액세스 토큰을 받아 앱에서 API를 호출합니다. 별도 서버, Web 클라이언트 비밀키, `google-services.json`, 앱에 저장하는 refresh token은 사용하지 않습니다. 최초 권한 동의 후에는 같은 계정을 지정하여 액세스 토큰을 다시 요청하고, 추가 사용자 동의가 필요하면 앱에서 다시 연결하도록 안내합니다. [인증서 등록과 토큰 갱신 설명](https://developer.android.com/identity/authorization)

## 4. 실제 연결 검사

1. 위 Android 클라이언트와 서명이 일치하는 APK를 Google Play 서비스가 있는 테스트 기기에 설치합니다.
2. 테스트 계정에 검사 전용 캘린더를 준비합니다. 실제 병원 자료는 넣지 않습니다.
3. 앱에 미래 날짜의 가상 예약을 만들고 **설정 → 병원·연락처 → 캘린더 연동 → 구글 계정으로 연결**을 누릅니다.
4. 등록한 테스트 계정과 캘린더를 선택하고 두 권한을 모두 허용합니다. **연동 시작** 후 구글 웹에 방문 하나가 일정 하나로 나타나는지 확인합니다.
5. 페리로그에서 시간을 수정하고 삭제하여 같은 외부 일정의 갱신·삭제를 확인합니다. 외부에서 제목을 바꿔도 페리로그가 유지되는지, **전체 다시 반영**으로 앱 내용이 돌아오는지 확인합니다.
6. 인터넷 끊김 후 예약 저장·재연결, 구글 권한 철회 후 **연결 다시 확인**, 앱 종료·재실행, 중복 생성 여부를 확인합니다. 검사가 끝나면 앱의 **연결 해제 → 페리로그가 보낸 일정도 삭제**로 검사 일정을 정리합니다.

프로젝트 ID, APK 커밋·서명 지문, 기기·OS, 검사 날짜와 실제 결과를 [캘린더 연동 검증 기록](캘린더-연동-검증.md)에 남깁니다. 액세스 토큰·인증 응답·실제 진료 내용은 기록하지 않습니다.

## 5. 오류와 공개 제공

- 계정 선택 후 권한 요청이 실패하면 OAuth 클라이언트의 **패키지명과 APK SHA-1**, 선택한 프로젝트의 API 활성화 여부부터 확인합니다. debug와 release 인증서를 혼동하지 마세요.
- 테스트 계정이 거절되면 **Audience → Test users**에 해당 계정이 있는지 확인합니다.
- 캘린더 목록이 비어 있으면 계정과 쓰기 권한을 확인합니다. 읽기 전용 캘린더는 선택 목록에서 제외합니다.
- 권한 일부만 허용하거나 이후 철회하면 전송은 중단되며, 페리로그 예약과 전송 대기 작업은 유지됩니다.
- 일반 사용자에게 공개하기 전 OAuth 동의 화면의 게시 상태와 해당 scope의 검증 요구 사항을 확인하고 필요한 검증을 완료합니다. 테스트 사용자만 연결한 결과를 공개 인증 검증 완료로 기록하지 않습니다. [Google OAuth 검증 안내](https://developers.google.com/workspace/calendar/api/auth)
