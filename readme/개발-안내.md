# 개발 안내

페리로그는 Galaxy Z 플립7을 우선 대상으로 만든 개인용 복막투석 기록 앱입니다. 로그인 없이 기록을 기기 내부에 보관하며, GitHub 업데이트 확인·다운로드에만 인터넷을 사용합니다. Android 12 이상을 지원합니다.

## 기능

- 시작 전 몸무게·혈압, 종료 후 초기배액량·기계 제수량 입력과 총 제수량 자동 계산
- 이전 실제 사용 구성 불러오기, 구성 이름·대표 색상, 과거 날짜 입력, 초안 보관
- 추가투석은 물품 사용만으로 저장하며 배액량 또는 배액무게를 선택 기록
- 품목 색상, EA 재고, 날짜별 일괄 입고, 사용기한, 사용·입고 취소, 현재 재고 확인
- 오늘·어제 미작성 안내와 완료 표현, 기록 목록·달력·기간별 표, 기간별 그래프·표
- JSON 내보내기·전체 복원, 선택 폴더에 자동 백업, 선택형 앱 잠금·기기 알림

## 개발 및 빌드

JDK 17, Android SDK 36, Build Tools 36, Gradle Wrapper 8.13을 사용합니다. Android Studio에서 이 폴더를 열거나 아래 명령을 실행합니다. SDK 위치는 `local.properties` 또는 `ANDROID_HOME`으로 설정합니다.

```sh
./scripts/build.sh :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

개발용 APK: `app/build/outputs/apk/debug/app-debug.apk` (`com.poyal.perilog.debug`).

처음 앱을 배포할 때만 서명 키를 생성합니다. 이미 배포한 앱을 다른 컴퓨터에서 빌드할 때는 기존 `.signing/` 폴더와 `signing.properties`를 프로젝트 루트에 복원하고 `assembleRelease`만 실행합니다. `.signing/`은 숨김 폴더입니다. SDK와 JDK 경로는 해당 컴퓨터에 맞춰 설정합니다.

```sh
./scripts/create-signing.sh
./scripts/build.sh :app:assembleRelease
```

설치용 APK: `app/build/outputs/apk/release/app-release.apk` (`com.poyal.perilog`). `.signing/`과 `signing.properties`는 버전 관리에서 제외합니다. **두 항목을 별도로 안전하게 보관하고 앱 업데이트에 같은 키를 사용해야 합니다.** 기존 키를 덮어쓰지 않습니다.

개발 버전 v1.0.4의 버전 코드는 5입니다. 기존 공개 v1.0.3의 버전 코드는 4입니다. 기존 앱과 같은 키로 서명한 APK를 배포합니다. Room 스키마 1→2→3 이전 검사가 기존 기록·사용 내역·초안·구성을 확인합니다.

에뮬레이터나 개발용 Android 기기가 연결된 경우:

```sh
./scripts/build.sh :app:connectedDebugAndroidTest
```

일반·큰 글씨·오프라인 E2E 반복 실행은 [E2E 테스트 안내](E2E-테스트.md)를 참고하세요.

GitHub Actions의 반복 실패와 긴 대기를 줄이기 위해 Android 검증 워크플로는 수동 진단으로만 실행합니다. 개발 중에는 관련 로컬 검사부터 수행하고, 확정한 릴리즈 후보의 전체 로컬 검증을 한 번 마치면 그 APK를 그대로 게시합니다. main·PR 푸시마다 전체 원격 검사를 실행하거나 원격 통과를 기다리지 않습니다.

UI 테스트는 개발용 패키지 데이터를 테스트 자료로 교체하므로 본인의 실제 기록은 출시용 패키지를 사용하세요.

## 구현 구조

- `data`: Room 엔티티·DAO·트랜잭션·감사 이력·버전 1 JSON 모델
- `domain`: 제수량 계산, 완료 조건, 이전 입력 선택, 재고 배정·실사 기준, 가져오기 검증
- `ui`: Compose 화면·입력 보조·ViewModel 상태
- `backup`: 파일 검증·복원 보호 백업·WorkManager·로컬 알림

재고는 저장된 입고·사용·실사 이벤트로 계산합니다. 치료 ID와 사용 ID를 연결해 재저장 시 중복 차감을 막습니다. 설정 복원도 치료·재고와 같은 트랜잭션으로 처리하기 위해 사용자 설정은 Room에 저장하고, 폴더 접근 권한과 백업 실행 상태는 DataStore에 별도로 보관합니다.

Room 스키마는 `app/schemas/`에서 관리합니다. 후속 DB 버전에는 명시적인 마이그레이션과 테스트를 추가해야 하며 파괴적 초기화는 허용하지 않습니다.

설계 이력은 [plan.md](plan.md), 설치·사용 방법은 [사용 안내](사용-안내.md), 검증 결과와 기기 확인 항목은 [검증 기록](검증-기록.md)을 참고하세요.

## 주요 기준

- 기계 총 제수량 = 초기배액량 − 이전 최종 주입 **설정값** + 기계 제수량. 설정 기본값은 2000mL이며 과거 기록에는 당시 기준을 보존합니다.
- 배액무게(g/kg)는 부피(mL)로 환산하지 않습니다. 기계투석과 손투석의 결과를 임의 합산하지 않습니다.
- 백업은 암호 없는 JSON입니다. 복원은 합치기가 아닌 전체 교체이며 사전에 현재 데이터를 보호 백업합니다.
- OS 클라우드 백업을 사용하지 않습니다. 인터넷 권한은 GitHub 업데이트 확인·다운로드에만 사용합니다. 사용자가 파일 선택기에서 선택한 저장 위치의 동작은 해당 파일 제공자에 따릅니다.

구현 시 참고한 공식 문서: [Android 빌드 도구](https://developer.android.com/build/releases/gradle-plugin), [Room](https://developer.android.com/jetpack/androidx/releases/room), [Compose 버전 조합](https://developer.android.com/develop/ui/compose/bom/bom-mapping).

## 문서용 실행 화면 촬영

루트 [README](../README.md)는 사용자 매뉴얼입니다. 개발·계획·검증 문서는 이 `readme/` 폴더에 보관합니다. `design/`은 초기 디자인 시안이며, 실제 앱 캡처와 구분합니다.

Android 에뮬레이터를 실행한 상태에서 다음 명령으로 화면 23장을 다시 촬영합니다.

```sh
PERILOG_SERIAL=emulator-5554 ./scripts/capture-screenshots.sh
```

`readme/capture/DocumentationCapture.kt`는 `-PcaptureScreenshots`가 있을 때만 Android 테스트에 추가됩니다. 촬영 전에 선택한 에뮬레이터의 개발용 앱 데이터를 초기화하고 예시 자료를 넣은 뒤 실제 화면을 PNG로 저장합니다. 출시용 패키지는 변경하지 않습니다. 개인 기기의 실제 기록에는 사용하지 않습니다. 결과는 `readme/screenshots/01-home.png`부터 `20-dark-mode.png`와 추가 화면 21~23까지입니다. 촬영 날짜에 따라 예시 날짜도 달라집니다.

## GitHub 릴리즈 게시

릴리즈 준비·게시·중단 후 재개 때마다 **[페리로그 전용 로컬 검증 후 배포 운영 가이드](로컬-검증-후-배포-운영-가이드.md)를 먼저 읽고 따릅니다.** [검증 기록 템플릿](releases/릴리즈-검증-템플릿.md)으로 해당 실행의 결과와 근거를 남깁니다.

로컬에서 검증한 서명 APK를 그대로 배포합니다. `.github/workflows/release.yml`은 태그의 APK·체크섬·스크린샷 ZIP을 업로드하고 공개하며 재빌드하지 않습니다. 서명 키를 Actions에 전달하지 않습니다. 현재 워크플로는 검사 결과·서명·업데이트 데이터 보존을 자동 확인하지 않으므로 **태그 푸시 전에** 운영 가이드의 필수 검사를 모두 확인합니다.

릴리즈 태그는 최종 main 소스·문서 커밋의 바로 다음에 `.release/`의 해당 버전 세 파일만 추가한 별도 커밋을 가리킵니다. 그 배포 커밋은 main에 합치지 않습니다. 빌드한 커밋·최종 소스 커밋·배포 커밋의 허용 차이는 운영 가이드에서 정합니다.

`vVERSION` 태그 푸시와 `release/vVERSION` 브랜치 푸시는 모두 실제 게시를 시작합니다. 중복으로 실행하지 않습니다. 기존 태그가 있지만 실행이 없는 경우에만 상태를 확인하고 수동 게시 경로를 사용합니다.

기존 릴리즈·태그·다른 바이트의 동명 파일을 덮어쓰지 않습니다. `scripts/publish-release.py`는 기존 초안과 공개 파일을 조회·검증하고 동일한 파일은 보존하며 누락 파일만 업로드합니다. 업로드 후 세 파일을 다시 내려받아 원본과 GitHub SHA-256을 확인한 뒤 공개합니다. 공개 파일 세 개를 다시 내려받아 원본과 서명을 확인한 뒤 게시 완료로 기록합니다.

## 업데이트 기능 검사

`./scripts/test-updates.sh`는 전용 에뮬레이터에서 작은 개발 서명 APK를 로컬 루프백 HTTP 서버로 제공해 DownloadManager, 체크섬 검증, 설치 화면과 취소 후 파일 보존을 확인합니다. GitHub 네트워크를 사용하지 않습니다. 실행 APK를 실제 설치하지 않고 설치 화면에서 취소합니다. 출시 키는 사용하지 않으며 `.tools/update-fixture/`에 검사 파일을 만듭니다.

일반 UI 검사는 `PerilogTestRunner`가 GitHub 응답을 대체하므로 실제 공개 버전과 무관합니다. 디버그 빌드만 루프백 HTTP를 허용하며 출시 빌드는 HTTPS를 사용합니다. 업데이트 메타데이터는 기기 DataStore의 `appUpdate` 키에 저장하고 기록 DB와 백업 JSON에는 추가하지 않습니다.
