# 구현 검증 기록

검증일: 2026-10-01. 사용자 실제 데이터 대신 격리한 개발용 패키지와 테스트 자료를 사용했습니다.

## 환경

- macOS arm64, JDK 17, AGP 8.13.2, Gradle 8.13
- compile/target SDK 36, 최소 SDK 31
- Android 16 / API 36 arm64 에뮬레이터, 1080×2400
- Galaxy Z 플립7 실기기는 연결되지 않았습니다.

## 자동 검증

| 검사 | 결과 |
| --- | --- |
| 도메인 단위 테스트 | 12개 통과 |
| Room 저장소 테스트 | API 31 및 35에서 총 8개 통과 |
| Android 에뮬레이터 테스트 | 5개 통과 |
| Android Lint | 오류 0, 버전 업데이트·테마 아이콘·KTX 등의 경고 있음 |
| 개인 설치 APK | 약 5.1MB, R8 및 리소스 축소, 서명 검증·업데이트 설치·콜드 실행 통과 |
| Manifest | INTERNET 권한 없음, 자동 클라우드/기기 전송 백업 제외 |

주요 시나리오:

- `(2300 − 2000) + 600 = 900`, 음수/0/미입력, 과거 기준 보존
- 기계/손투석 완료 조건, 배액 질량과 부피의 분리, 이전 구성 선택에서 미래 기록 제외
- 기한별 배정, 만료 제외, 임박 7일/8일/당일/무관/잔량 0 경계
- 재고 부족 시 미배정, 현재 재고 실사 이전 이력의 중복 차감 방지
- 동일 기록 반복 저장·수량 수정·삭제 후 사용 유지·되돌리기·사용 취소
- 초안은 재고를 차감하지 않으며 반복 복원이 사용량을 다시 차감하지 않음
- 손상되거나 지원하지 않는 버전·중복 ID·잘못된 참조의 백업 거절
- 실제 화면에서 기계 기록 → 900mL 결과 → 재고 10→8EA → 손투석 물품 저장 → 6EA
- 품목 등록 및 일괄 입고 화면에서 12EA 저장, 사용기한 기본 무관
- 백업 파일 쓰기·재읽기·전체 복원 및 복원 전 보호 파일 생성
- 작성 중 몸무게의 Activity 재생성 후 복구 및 가로 화면, 재고 미차감
- 통계에서 30D·표를 선택하고 기록 상세를 다녀온 뒤 선택 상태 유지

보고서는 `app/build/reports/tests/testDebugUnitTest/`, `app/build/reports/androidTests/connected/debug/`, `app/build/reports/lint-results-debug.html`에서 확인합니다. 일반 개발 브랜치에는 빌드 산출물을 포함하지 않습니다. 릴리즈 태그의 별도 배포 커밋에는 검증한 서명 APK와 배포 파일을 보관합니다.

## 실제 실행 화면

아래 이미지는 에뮬레이터의 가상 테스트 데이터입니다. 승인된 디자인 시안과 구분합니다. 사용자 승인에 따라 매뉴얼에도 에뮬레이터 촬영 환경을 표시했습니다.
